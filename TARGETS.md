# Target review

This assessment uses the latest saved genuine TinyFish Monitor result for each of the 20 registered pages. Likelihood reflects the type of update and the content visible to Monitor. No target was changed during the reliability follow-up.

| Target | Likelihood in a short window | Evidence to look for |
| --- | --- | --- |
| [Cloudflare Status](https://www.cloudflarestatus.com/) | High | Multiple visible maintenance locations and dates. Look for a new incident or a maintenance status transition. |
| [GitHub Status](https://www.githubstatus.com/) | High | Visible incident history and a recent resolution. Look for a new or updated incident entry. |
| [Cloudflare Changelog](https://developers.cloudflare.com/changelog/) | High | Several dated entries from the latest observed day. Look for a new entry or a substantive feature update. |
| [Chrome Releases](https://chromereleases.googleblog.com/) | High | Distinct channel and platform release posts. Look for a new build or post. |
| [GitHub Changelog](https://github.blog/changelog/) | High | Recent dated releases and retirements. Look for a new headline or substantive entry edit. |
| [Vercel Changelog](https://vercel.com/changelog) | High | Named product changes in the extracted content. Look for a new announcement. |
| [OpenAI Status](https://status.openai.com/) | Medium–high | Component state and availability history are visible. Look for an incident or component status transition. |
| [GitLab Status](https://status.gitlab.com/) | Medium–high | Operational status is visible. Look for incident or maintenance text and disregard the page clock. |
| [Vercel Status](https://www.vercel-status.com/) | Medium–high | Per-component status is visible. Look for component degradation or an incident update. |
| [Google Cloud Status](https://status.cloud.google.com/) | Medium | Incident and product status sections are visible. A clock-only update has already been excluded. |
| [AWS Health](https://health.aws.amazon.com/health/status) | Medium | Service health sections are visible. Require an incident or maintenance change and disregard auto-refresh text. |
| [Kubernetes Blog](https://kubernetes.io/blog/) | Medium | A dated post list is visible. Look for a new article. |
| [Node.js Releases](https://nodejs.org/en/blog/release) | Medium | Release listings are visible but short in the current extraction. Look for a new version headline. |
| [Firefox Release Notes](https://www.mozilla.org/en-US/firefox/releases/) | Medium | Browser version links are visible. Look for an added version. |
| [Python Release Index](https://www.python.org/downloads/) | Medium | Active release table and download entries are visible. Look for a new version or support-status change. |
| [GitLab Releases](https://about.gitlab.com/releases/categories/releases/) | Lower | Redirected documentation index groups releases by minor version. Look for a version listing change. |
| [Playwright Release Notes](https://playwright.dev/docs/release-notes) | Lower | Versioned release notes are visible. Meaningful changes depend on a release or published correction. |
| [Azure Status](https://azure.status.microsoft/en-us/status) | Lower | The public page covers widespread incidents. Look for a published incident or region state change. |
| [AWS What's New](https://aws.amazon.com/new/) | Lower observed coverage | The captured text contained the announcement shell and loading text. Visibility is the limiting factor. |
| [Google Security Blog](https://security.googleblog.com/) | Lower observed coverage | The captured text was mostly navigation and preferences. Look for actual published headlines before counting a change. |

Review the old and new substantive text and both capture timestamps before using a change as submission evidence.
